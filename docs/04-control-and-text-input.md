# 04 鼠标、键盘与中文输入设计

## 1. 输入路径

鼠标采用 `--mouse=sdk`，使用手机屏幕绝对坐标。键盘首选 `--keyboard=uhid`；手机将其作为实体键盘，输入法在手机端处理。UHID 可以走无线连接；AOA 依赖 USB，不作为无线方案的后备。[R3][R12]

SDK 键盘只保证 ASCII 和部分其他字符，不能用 `adb shell input text` 或逐键替换拼凑通用中文输入。电脑输入法的候选窗和手机输入法的候选窗必须明确区分，避免用户误认为两者自动同步。

所有资料编号见[参考资料](09-references.md)。本章中的输入策略和事务流程属于需要实现的产品能力。

## 2. 鼠标操作

| 操作 | 设计行为 |
| --- | --- |
| 左键单击 | 对应一次触摸按下/抬起 |
| 左键按住并移动 | 拖动或滑动，不由软件猜测手势意图 |
| 左键长按 | 持续按住；长按判定由手机 App 完成 |
| 滚轮 | 映射至当前手机界面的滚动 |
| 右键 | 返回；上游对应情况下可唤醒显示屏 |
| 中键 | 手机桌面 |
| Ctrl + 左键拖动 | 在 SDK 鼠标模式模拟双指缩放/旋转 |

上游已有基本映射，但最终手势效果取决于手机应用。[R5][R12] 首版不默认启用捕获鼠标指针的 UHID 鼠标模式，不占用全局鼠标钩子。

### 2.1 坐标

以视频内容矩形为输入边界，先从桌面物理像素/窗口坐标转换到渲染内容矩形，再映射到当前帧尺寸。XAML DIP、Win32 物理像素、SDL 窗口坐标和 SDL 像素尺寸必须分别命名，不得混用。

对于内容矩形 `(L,T,W,H)`、当前帧尺寸 `(Fw,Fh)`，无旋转附加变换时：

```text
fx = floor((x - L) * Fw / W)
fy = floor((y - T) * Fh / H)
```

先判断点是否位于内容矩形；黑边点击直接忽略，不把坐标裁到最近边缘形成误点击。最后只对浮点误差进行边界约束。优先复用 scrcpy 原生映射，不在管理界面重复实现一套方向变换。[R15]

旋转/折叠后等待新的尺寸事件，冻结新的按下事件，释放旧手指，再使用同一帧代的变换。不能显示新方向却仍按旧方向发坐标。

### 2.2 鼠标越界与失焦

仅在本次按下发生于视频内容区时启用必要的拖动捕获；松开后立即释放，不改变 Windows 全局指针行为。失焦、最小化、文字面板开启、只读切换和断线都要释放全部按钮及虚拟手指。

工具栏与菜单的点击由桌面 UI 完整消费，绝不投递到视频。窗口重新获得焦点时，第一次用于激活窗口的点击是否同时传手机按一致规则处理：默认仅激活，第二次再操作，避免误触。

## 3. 键盘

### 3.1 UHID 首选

首次使用可提示配置手机实体键盘布局；提供用户主动打开手机实体键盘设置的入口。不要自动改写手机默认输入法、语言、系统键盘布局或输入法偏好。[R3]

手机中文输入法对实体键盘的候选、选词和标点处理需要真机测试。记录实际 UHID 可用性，不按 Android 版本号直接宣布成功。

UHID 初始化失败：保留投屏，提示“实体键盘模式不可用”。可由用户选择兼容键盘（SDK）或文字面板；不得暗中切到只支持部分字符的路径却继续显示“中文输入正常”。若 SDK 注入也因 OEM 权限失败，禁用对应控制并保留仅观看。[R1][R3]

### 3.2 焦点与按键释放

只在当前前台视频 HWND、当前活动 session、控制允许、未打开桌面面板时转发。菜单、文件对话框、文字面板、其他应用拥有焦点时禁止发送新键。

维护已按下的键、修饰键、鼠标按钮集合。每次失焦先按已发送状态发释放事件，然后清空本地集合。UHID 需要零按键状态报告，SDK 需要匹配的抬起事件。断线后不能发出的释放不得排队留到新会话，新的 UHID 设备从空状态开始。

不将 Win+L、Alt+Tab、Ctrl+Alt+Delete 等 Windows 系统切换行为重映射为手机命令。应用快捷键仅在应用窗口内生效，不能占用用户其他输入助手的全局快捷键。

### 3.3 快捷键约定

F11：全屏切换。Esc：有菜单时关闭菜单；全屏时优先退出全屏；文字面板时关闭面板；其他情况下不额外绑定手机返回。

Ctrl+C / Ctrl+X：正常传给手机，作用由手机应用决定，不自动把手机剪贴板复制到电脑。

Ctrl+V：产品定义为用户主动请求粘贴电脑当前的纯文本剪贴板；执行前读取一次，不监听后续变化。显式拦截后只能走一条粘贴路径，不能同时把原始 Ctrl+V 再转发一次。

上游 `--no-clipboard-autosync` 会影响 Ctrl+V 的自动预同步；只设置此参数不会自动实现本产品的“显式跨设备粘贴”语义，必须定制相应路径。[R5][R15]

首版不提供手机剪贴板后台读取与同步。需要把手机内容复制回电脑时，列为后续显式功能，不借 Ctrl+C 偷加跨设备同步。

## 4. 电脑中文文字面板

### 4.1 编辑与确认

使用本地 WinUI 文本框，正常调用 Windows 输入法。IME composition 期间仅更新编辑状态；用户确认的正文才可参与插入。不得把 TextChanged 逐次当作最终文本发送。

插入按钮在文本为空、超过限制、会话非活动、仅观看、等待前一请求结果或 IME 组合尚未完成时禁用。Enter 始终留给编辑框和输入法；不自动发送消息。保留原始空格、换行、全角标点和 Unicode 序列；不做翻译、润色、归一化或自动补句末标点。

默认最大 UTF-8 长度 16,384 字节；计算序列化后的 IPC 长度并同时校验 65,536 字节消息上限。不能按 C# UTF-16 字符数量替代 UTF-8 字节数。过长内容明确提示分段，首版不自动切块粘贴，避免多次动作破坏文本顺序。

明确提示“请先在手机上点选输入框”。不读取手机 UI 树、截图 OCR 或猜测密码框；安全输入框、禁止粘贴的 App 和远端焦点变化属于已知限制。

### 4.2 文本传输

面板正文通过本地管道进入定制引擎，直接构造设置手机剪贴板的控制消息。Windows 剪贴板不被覆盖，不使用“暂存电脑剪贴板、写入正文、再恢复”的做法，避免污染剪贴板历史以及覆盖用户并发复制的新内容。

手机剪贴板将被替换，可能受手机系统及第三方输入法影响；用户界面和隐私说明明确告知。不承诺敏感文字仅被目标 App 看见，也不自动读取并恢复手机旧剪贴板。[R5]

首选序列：设置手机剪贴板但不立即粘贴 → 等待匹配序号回执 → 通过已选键盘通道发送一次粘贴快捷键并释放修饰键。若平台仅支持另一条经验证的显式粘贴路径，记录能力与测试，不在一次请求中并行调用两条路径。

回执只表示协议层处理，不证明目标应用已插入，更不证明消息已发送。即使收到回执，提示也采用“已请求插入，请在手机确认”。

## 5. 文本事务与防重复

### 5.1 状态

```text
Editing → Queued → ClipboardRequested → ClipboardAcknowledged
       → PasteDispatched → CompletedAtTransportLevel
                         ↘ Failed / DeliveryUnknown / Cancelled
```

每次用户主动点击拥有新的 requestId 和本会话单调递增的 inputSequence。`inputSequence` 在 JSON 中按十进制字符串传输，避免整数精度差异，运行时按 UInt64 校验。

引擎维护本会话最后接受的输入序号。小于等于该序号的请求不得再次执行；相同 requestId 返回缓存状态。最近 256 个请求可保存状态摘要，缓存淘汰不允许旧序号再次执行。新会话拥有新 sessionId，旧会话请求全部拒绝。

局部队列接收与手机端回执分别记录；仅保存 requestId、序号、阶段和非敏感错误码。任何重连路径不得重新入队旧 TextRequest。

### 5.2 超时语义

提交后明确尚未发往手机便失败：显示“未发出，请重试”，仍由用户决定再次点击。

已发出设置剪贴板或粘贴事件，但确认丢失：显示“结果未确认，请先检查手机”，不自动重试，不清空面板正文。

协议回执收到但 App 拒绝粘贴：程序未必能观察到。不能显示“输入成功”，不能尝试降级为逐字注入。用户可在手机重新选中输入框后发起新的请求。

此设计保证本软件不自动重复执行同一请求，不宣称跨应用端到端 exactly-once。手机或 App 的外部行为不在协议回执的证明范围内。

### 5.3 取消与正文清理

发送前可取消并清理；发出后取消不能撤销手机端已经发生的剪贴板变化或输入。取消界面应体现这一点。

成功请求后可清空面板；失败/未确认时在当前进程内保留正文便于用户检查，关闭面板或应用后丢弃。不保存输入历史、不写临时文件、不进入崩溃附件。

## 6. 仅观看模式

只有桌面本地全屏、置顶和电脑播放静音可以保留。所有手机输入、剪贴板写入/读取、手机屏幕电源、音量和打开手机设置都被拒绝。

切入仅观看前释放已有输入，清空待执行文本，关闭文本入口。第一版允许重启引擎并使用 `--no-control` 获得明确边界；切回可控制同样需要用户主动操作。运行时切换若实现，必须在原生输入与 IPC 入口双重限制，而非只把按钮置灰。[R5]

仅观看不撤销 ADB 授权，用户仍须信任这台电脑。详见[安全设计](05-security-and-data.md)。
