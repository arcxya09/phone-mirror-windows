# 07 开发阶段、任务拆分与交付

## 1. 当前交付

阶段 D0：设计文档包。包含完整规格、接口和配置样例、测试计划、架构决策、第三方来源及文档校验工具。没有应用源码、实际引擎补丁、安装包或测试过的手机兼容清单。

应用里程碑按照验收证据推进，不在文档中承诺固定日历工期。未经真机验证的技术路径不得直接宣布已经实现。

## 2. M0 技术验证

目标：证实最关键且不可由 UI 掩盖的依赖关系。

| 工作包 | 内容 | 完成证据 |
| --- | --- | --- |
| M0-01 | 锁定 scrcpy/ADB 候选与 Windows 构建链 | 来源、下载校验、完整版本与可重复构建记录 |
| M0-02 | 无线配对、端口分离、设备发现新旧能力检测 | 真机配对与改端口后重新发现记录 |
| M0-03 | ADB 服务与密钥目录隔离，和其他 ADB 共存 | 文件/进程/端口观察，不触碰全局配置 |
| M0-04 | 原生窗口与 UHID、声音 | 至少 Android 11 和一个新系统的基础链路记录 |
| M0-05 | 本地文字设置剪贴板与回执路径 | 中文正确、Windows 剪贴板不被覆盖、不重复 |
| M0-06 | 工具区与视频窗口的焦点/DPI 原型 | 125%/150%/200% 与多屏下无错位 |
| M0-07 | 供应链与再分发梳理 | 原创许可证决策、打包依赖清单、上游义务清单 |

M0-03 或 M0-05 未达标即阻止进入对外 Alpha，不允许用全局 ADB 或临时覆盖电脑剪贴板替代。工具区实现可以在原生操作区与关联窗口之间调整，但必须记录 ADR 并通过 M0-06。

## 3. M1 最小连接闭环

建立 WinUI 工程和核心测试项目；实现设备页、配对码向导、手动地址、已配对设备记录、单会话状态机、启动/停止和基础诊断。完成引擎版本验证和结构化 Ready/FirstFrame/Stopped 事件。

交付目标：内部 Alpha，能够在基准设备上通过电脑完成配对、连接、观看、鼠标键盘操作并退出。若仍缺文字面板和拖放禁用，必须在构建名称与说明中标明“技术验证版”，不作为完整产品发布。

## 4. M2 完整交互与输入

实现小范围 scrcpy 客户端定制、命名管道、工具区、文字面板、焦点释放、Ctrl+V 单一路径、防重复序号、仅观看和手机显示屏控制。

补齐全屏、置顶、窗口记忆、主题、可访问性和错误文案。关闭后台剪贴板同步及文件拖放功能。通过完整 I/T/U 类测试后进入 Beta。

## 5. M3 稳定性与兼容性

实现有限重连、取消竞态处理、锁定休眠停止、音频降级、异常退出回收和诊断导出。按真实组合扩展手机和输入法矩阵，执行两小时稳定性测试、资源统计和网络故障注入。

发现问题先修复，不用增加更多功能稀释稳定性工作。记录实际支持范围；无法支持的 OEM/系统组合应明确显示原因或使用限制。

## 6. M4 打包与发布

输出便携 ZIP 与用户级安装包；根据实际运行时依赖选择自包含部署或明确随包安装的依赖，普通用户电脑无需 Visual Studio 或 Android Studio。

应用、引擎、手机端组件和依赖必须成套发布；不允许在线临时抓取未验证的 latest 依赖。首版不做自动更新；用户主动替换为完整新包，配置迁移需有回退策略。

每个发布包包含产品版本、引擎补丁版、上游清单、SHA256、第三方许可证与变更记录。不承诺没有代码签名的安装包不会触发 Windows 警告；签名与信誉属于单独的发布工作项。

卸载默认删除程序；用户可选择删除本应用配置与配对数据。禁止删除全局 ADB、全局 SDK 或其他工具的信任关系。

## 7. 预定工程目录

以下路径为后续工程布局，不表示本包已有对应源码：

```text
src/PhoneMirror.App/              WinUI 页面与组合根
src/PhoneMirror.Core/             状态、配置、设备模型、输入事务
src/PhoneMirror.Infrastructure/   ADB、进程、管道、日志实现
native/scrcpy-patches/            基于固定标签的小范围补丁
native/engine-bridge/             管道和桌面行为适配
build/                           可重复构建及依赖锁
packaging/                       便携和用户级安装包定义
tests/unit/                      核心规则测试
tests/integration/               Windows 组件/进程测试
tests/device/                    真机脚本与非敏感记录
```

优先保持 Core 不依赖 WinUI/ADB 真机，从而可以自动测试状态机和输入策略。所有可能阻塞的系统调用放在有取消与超时的基础设施层。

## 8. 变更与审查规则

每个实现提交关联需求 ID 或测试 ID；先更新接口契约，再修改通信双方。修改上游版本必须提交补丁重放结果、契约测试和真机回归。

禁止凭已有其他 Windows 项目直接继承无关功能、用户内容或许可证要求。不得将密钥、日志、设备截图、用户设备名称和任何个人工作数据提交到公开仓库。

需求扩展先提出范围变化和维护代价；首版不追加 AI、账号和云服务。当前设计对实际设备型号仍无假定，实施时以目标手机实测为准。

## 9. 完成定义

代码已提交、可从干净 Windows 构建、依赖可核验、对应自动测试通过、真机验收有证据、权限/隐私行为符合规格、用户说明准确，才可将工作包标记完成。只有文档、UI 截图或原始 scrcpy 能运行，不能证明完整软件已经交付。
