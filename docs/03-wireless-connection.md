# 03 无线配对、发现与连接状态机

## 1. 两类端口与三种成功

手机配对界面显示配对服务端口；无线调试首页或连接服务广播提供实际连接端口。两者独立，均可能变化。PC 本机 ADB server 端口是第三个概念，与这两个手机端口无关。

配对成功只表示建立信任；ADB 设备状态为 device 表示建立调试连接；首帧回调才表示画面显示成功。产品分别维护 PairingState、TransportState 和 SessionState。[R2][R7]

## 2. 发现后端

使用受控 ADB 提供的 mDNS 发现。候选 Platform-Tools 37.0.1 使用 libadbmdns，旧 `ADB_MDNS_OPENSCREEN` 已无效；不能把强制打开旧后端作为默认修复。[R8]

优先检测 `server-status` 与 `mdns track-services` 能力，支持时使用事件流；只支持 `mdns services` 时使用限频轮询。具体输出格式与解析测试按锁定版本固化，不能仅凭版本字符串假定命令可用。

旧 ADB 手册与当前发布说明不一致时，以锁定版本的 `--help`、实际输出和对应源码为准。UI 前台发现轮询后备间隔 2 秒；隐藏时 10 秒；应用退出、电脑锁定和休眠时停止。保留手动地址流程，不安装 Bonjour 作为默认前置依赖。

识别 `_adb-tls-pairing._tcp` 与 `_adb-tls-connect._tcp`。广播元数据没有完成设备认证，名字、地址和显示型号都按不可信输入处理。限制字段长度、删除控制字符、拒绝异常端口值。

Android 17 / ADB Wi-Fi 2.0 的信任网络和发现增强作为能力分支，不提高首版 Android 11 的最低目标，也不把所有手机都描述为支持相同自动重连行为。[R2]

## 3. 首次配对步骤

1. 用户在手机上明确打开配对码页面。
2. 电脑发现候选；用户选择一台，或手工填写配对地址。
3. 输入六位数字，执行受控 `adb pair`。首选从标准输入传入配对码，避免进程命令行和诊断记录暴露。该能力在锁定 ADB 上用集成测试确认。[R2][R9]
4. 校验进程退出码和结构化/受限解析结果。发现矛盾时显示失败，不依靠单独字符串包含 success。
5. 立即清理配对码；保留临时配对事务 ID，并从当前发现快照重新寻找连接端点。
6. 用已获授权的连接建立设备会话，读取最小必要设备信息并绑定本地记录。
7. 找不到连接端点时不重新要求配对；显示“配对完成，请填写无线调试首页的连接地址”。

示意命令：

```text
adb -H 127.0.0.1 -P <local-adb-port> pair <phone-ip>:<pairing-port>
adb -H 127.0.0.1 -P <local-adb-port> connect <phone-ip>:<connection-port>
adb -H 127.0.0.1 -P <local-adb-port> devices -l
```

命令由参数数组构造，不由 shell 执行；码不作为示例中的参数。IPv6 采用方括号地址与单独端口解析，保留所需的接口 scope；不把包含多个冒号的地址直接按冒号拆分。

配对界面总等待建议 120 秒，单次命令上限 20 秒。手机上配对码失效优先于软件倒计时。用户取消后最多执行局部清理，不自动撤销其他授权。

## 4. 身份与地址更新

设备本地 UUID 只用于应用记录。名称、IP、同型号和过去出现过的端口都不足以自动判定为同一手机。

配对过程中记录可信 ADB 提供的配对关联信息；认证连接后再读取可用的稳定标识。字段缺失或不唯一时要求用户在候选列表选择，不将第一台在线设备默认替代目标设备。

每个会话固定目标 transport selector；所有命令带目标和当前 generation。已配对但非目标设备上线时，只更新列表，不自动投屏，不执行读取内容的指令。

网络改变后失效旧地址缓存，重新发现并验证。不能无限尝试旧 `IP:port`；新地址认证失败时不得回落到未配对或明文连接。

自动连接偏好针对本地设备记录和可信网络上下文。网络识别不确定时降为手动，不仅凭 SSID 字符串认定为原网络。

## 5. 会话状态机

| 状态 | 进入条件 | 允许操作 | 下一状态 |
| --- | --- | --- | --- |
| Idle | 无活动会话 | 添加、选择设备 | Discovering / Pairing |
| Discovering | 检索候选端点 | 取消、手动地址 | Connecting / Idle |
| Pairing | 用户提交有效格式配对码 | 取消 | Discovering / Failed |
| Connecting | 对明确目标建立认证连接 | 取消 | Starting / Failed |
| Starting | 启动匹配引擎并等首帧 | 取消 | Streaming / Failed |
| Streaming | 首帧显示、链路可用 | 控制、只读、断开 | Reconnecting / Stopping |
| Reconnecting | 原活动会话意外掉线 | 取消 | Starting / Failed |
| Stopping | 显式关闭或系统安全事件 | 不接受新输入 | Idle |
| Failed | 不可恢复错误，附阶段与错误码 | 重试、诊断 | Discovering / Idle |

音频和键盘兼容性作为能力子状态，不与会话状态交叉枚举。例如 `Streaming + audioUnavailable + keyboardFallback` 仍保留可看的画面。配对失败、连接失败、启动失败和恢复超时通过 Failed 的阶段与错误码区分，不新增未定义的枚举值。

只有 SessionCoordinator 更新状态；UI 订阅不可变快照。一个设备至多一个配对/连接任务；全局同时一个投屏任务。任何异步回调先核对 sessionId / generation / cancellation。

## 6. 超时、重连和退避

| 阶段 | 初始设计限额 | 超限结果 |
| --- | --- | --- |
| 本地 ADB 就绪 | 5 秒 | 说明依赖启动失败 |
| 发现首次结果 | 8 秒 | 保留重试，显示手动入口 |
| 单次配对命令 | 20 秒 | 提示检查配对页和码 |
| 调试连接 | 10 秒 | 回到可重试状态 |
| 引擎首帧 | 10 秒 | 分离启动/采集错误 |
| 当前会话恢复 | 30 秒总预算 | 停止自动重试 |
| 正常停止 | 3 秒 | 终止自有进程树 |

使用单调计时器，避免系统时钟变化影响预算。断线恢复采用短退避，建议等待 1、2、4、8 秒并加入少量抖动；单次发现/连接/首帧均服从剩余总预算，不能四次完整 10 秒叠加越过 30 秒。

重连开始立即释放输入，丢弃未发送事件；对文字请求标记未确认。重新连通也不重放输入，不自动按 Enter，不更换手机，不提升到更高权限模式。

只对意外链路丢失触发有限恢复。用户点击断开、关闭窗口、切到仅观看失败、Windows 锁定/休眠、设备明确撤销授权，均不得自动开始新的控制会话。

## 7. ADB 共存与凭据隔离

首选本应用私有 ADB 实例：独立回环监听端口、明确二进制路径、独立用户数据目录、可追踪进程归属。`-P` / `-L` 是服务端口机制，不能把“拷贝一个 adb.exe”当作实例隔离。[R9]

M0 必须验证以下组合：管理进程的 ADB 命令、scrcpy 自行启动的 ADB 子进程、配对操作以及重新启动的服务端，都使用同一个指定端点和同一套凭据。

`ANDROID_USER_HOME` 是工具用户配置目录的候选重定向机制，但必须用该版本 ADB 的实际文件访问验证；`ADB_VENDOR_KEYS` 添加可选密钥不等于禁止默认用户密钥加载，不能单靠该变量实现隔离。[R11][R16]

不能通过改动 Windows 全局环境变量、用户默认 `.android`、Android Studio 配置或系统 PATH 解决隔离。应用仅修改自有子进程环境。若隔离未通过 M0，阻塞首版交付，不静默改用全局服务。

私有端口仅监听回环，不使用 `adb -a`。**回环 TCP 端口不等于当前用户独占安全边界**；其他本地进程可能访问 ADB smart socket，必须在安全说明中明确。应用层命名管道 ACL 保护管理 API，不能声称其同时保护了 ADB 自身端口。

## 8. 删除记录和撤销授权

“删除本地设备记录”停止该设备会话，移除应用中的元数据和自动连接许可。发现层不得将它立即重新加入已允许列表；ADB 底层已有信任可能仍存在，不能把本地删除等同手机撤销。

“撤销授权说明”引导用户在手机无线调试的“已配对设备”中删除本电脑。[R2] 这不需要抹除其他工具的密钥。

“清除本应用全部配对数据”属于破坏本应用配对状态的操作，需要二次确认：停止自有 ADB，删除自己的密钥和已知主机数据，重建后所有本应用手机需要重新配对。不得删除用户全局 `.android` 或宣称远端授权记录已经消失。

## 9. 网络异常诊断

区分本地服务失败、mDNS 无结果、手动端点不可达、认证失败、设备离线、引擎无首帧。不能因为广播列表为空就断言路由器故障，手机未开无线调试也会造成同样现象。

面向用户只给对应动作：保持手机配对页面、读取正确端口、检查局域网隔离、确认受管理设备是否允许调试。不得引导关闭整个防火墙、放开所有端口、打开公网映射或长期监听 5555。

手动连接只能绕过发现，无法绕过网络隔离或设备权限。企业网络/VPN/多网卡环境单独测试；首版不自动修改路由表或网络适配器优先级。
